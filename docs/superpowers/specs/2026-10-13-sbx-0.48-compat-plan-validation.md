Ces affirmations remplacent la relecture du plan. Répondez ligne par ligne ; vos réponses sont enregistrées au fil de l'eau et je les relis depuis la session. Le plan sera aligné sur cette fiche, jamais l'inverse.

## Contexte

Le plan met en œuvre la spec de compatibilité sbx v0.48.0, déjà validée : den lit les nouvelles sorties de `sbx ls`, `sbx template ls` et `sbx version`, et exige sbx v0.48.0. Il tient en quatre étapes : plancher de version, lecture des listes, documentation, contrôle sur la machine de développement. Cette fiche ne rouvre pas la spec ; elle valide les choix que le plan ajoute. Valider toutes les lignes autorise l'implémentation selon le mode d'exécution retenu ici.

## Glossaire

- **ancienne forme** : Sortie JSON de `sbx ls` et `sbx template ls` jusqu'à v0.47.0 : un objet qui enveloppe la liste (`{"sandboxes": [...]}`). Depuis v0.48.0, sbx renvoie la liste seule.
- **exécution native** : Claude implémente les quatre étapes dans la session en cours ; un relecteur neuf relit toute la branche à la fin.
- **exécution par sous-agents** : Un agent neuf implémente chaque étape et un relecteur neuf la vérifie avant l'étape suivante ; une relecture de toute la branche suit.
- **kits v3** : Format de kit sbx apparu en v0.45.0 (workload et mixins). den génère aujourd'hui des kits v2.

Réponse vide = ligne non traitée. La fiche gagne sur le document qu'elle valide.

## C — Ce que vous n'avez pas à valider

Détail technique du plan, vérifié dans le code. Si un de ces points contredit A ou B, c'est A ou B qui gagne.

**Étapes**

- **1. Plancher** : `MinVersion` passe à v0.48.0 ; `ParseVersion` lit les deux écritures ; nouveau message « too old » de `den doctor` ; le faux sbx des tests répond la nouvelle écriture.
- **2. Listes** : une fonction `decodeList` dans `internal/sbx/json.go`, partagée par `Ls` et `Templates` ; elle garde la tolérance à la bannière de mise à jour et refuse l'ancienne forme avec le remède.
- **3. Documentation** : §14.4 de la spec principale recopié par script depuis le §1 de la spec du 13 octobre ; paragraphe de CLAUDE.md réécrit.
- **4. Contrôle** : `task build`, `den ls`, `den doctor`, `den shell am`.

**Tests ajoutés ou réécrits**

- Ancienne forme refusée avec le remède, pour `sbx ls`, `sbx template ls` et la commande `den ls`.
- `[]` et `null` donnent une liste vide ; une chaîne ou un nombre donne l'erreur générique avec la sortie brute.
- `sbx version v0.48.0` avec et sans hash, ancienne écriture, ligne vide.
- `den doctor` : v0.47.0 en ancienne écriture jugée trop ancienne ; v0.48.0-dev et v0.49.0 acceptées ; v0.47.0-3-g… refusée.

**Garde-fous**

- `task check` avant chaque commit ; aucun test ne lance sbx.
- Le nouveau décodeur refuse toute fixture restée dans l'ancienne forme : un oubli de migration fait échouer la suite.
- Le registre d'identifiants de converge n'est pas touché.
