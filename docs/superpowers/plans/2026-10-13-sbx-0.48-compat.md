# sbx v0.48.0 Compatibility Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make den work on sbx v0.48.0: decode the bare JSON arrays of `sbx ls --json` and `sbx template ls --json`, read the new `sbx version` spelling, and raise the floor to v0.48.0.

**Architecture:** All changes sit in `internal/sbx` (the layer that owns sbx's output formats) plus the one floor verdict in `internal/cli/doctor.go`. One shared helper, `decodeList`, reads a listing for both `Ls` and `Templates`, and refuses the pre-v0.48.0 object shape with an upgrade remedy. Test fixtures move to the new shapes by a mechanical rewrite; the new decoder refuses any fixture left behind.

**Tech Stack:** Go, `encoding/json`, `golang.org/x/mod/semver`, Taskfile (`task check`).

**Spec:** `docs/superpowers/specs/2026-10-13-sbx-0.48-compat-design.md` (French). Its validation record `docs/superpowers/specs/2026-10-13-sbx-0.48-compat-validation.md` wins over it on any conflict.

## Global Constraints

- Floor: `sbx.MinVersion = "v0.48.0"`. `den doctor` is the ONLY command that judges it; no other command runs `sbx version` before working.
- No compatibility with sbx v0.47.0 or older: den never decodes the old `{"sandboxes":[…]}` / `{"images":[…]}` shape; it only recognizes it to refuse.
- Old-shape refusal text, exact: ``sbx <command>: output has the pre-v0.48.0 shape — den requires sbx v0.48.0 or later; upgrade sbx, then check with `den doctor` `` (the version comes from `MinVersion`).
- Doctor too-old text, exact: ``sbx <v> is too old: den requires v0.48.0 or later — the `ls --json` and `template ls --json` shapes and the `sbx version` output changed in between; upgrade sbx``.
- `ParseVersion` reads both `sbx version: vX …` and `sbx version vX …`.
- `DecodeJSON` (update-banner tolerance) stays and stays in the decode path.
- No change to the registry-credential write in `internal/converge/sbx.go`.
- Code, comments, messages in English; the spec under `docs/superpowers/` in French.
- Comments: a "why" at the decision site, matching the surrounding density. No change-narration ("now", "since v1.13.0", "was").
- No test calls `t.Parallel()`, opens a socket, or spawns a process. Goldens are edited by hand.
- Run tests with `-count=1`. `task check` is the gate before every commit; gofmt is enforced.
- Exclude `.claude/worktrees/` from every grep and every rewrite: it is a shadow copy of the tree.

## Review Focus

1. A JSON scalar at the top of a listing (`"error"`, `42`) → the generic `unreadable JSON output` error quoting the raw output, never an empty list. Test added in Task 2.
2. A user still on sbx v0.47.0 runs `den ls` (not `den doctor`) → the error names the upgrade and `den doctor`. Test added in Task 2 (`internal/cli/ls_test.go`).
3. `sbx version v0.48.0` with no commit hash, or a bare `sbx version` line → `"v0.48.0"` and `""`. Cases added in Task 1.
4. The update banner behind a bare array → still decoded. Covered by the migrated `TestLsIgnoresTheUpdateBannerAfterTheJSON` / `TestTemplatesIgnoreTheUpdateBannerAfterTheJSON` in Task 2; Task 2 Step 5 checks they still run.
5. A source manifest's `requires.sbx` with the new version spelling → `converge.checkCompatibility` reads it through `ParseVersion`; `sbx.Machine` answers the new spelling after Task 1, so the converge suite exercises it.

```go
// ParseVersion reads the version out of `sbx version`, whose output is one
// line: "sbx version v0.48.0 <commit>" from v0.48.0 on, "sbx version: v0.43.0
// <commit>" from v0.38.0 to v0.47.0.
//
// Both spellings are read although den supports only v0.48.0 and later: the
// old one is what an sbx below the floor prints, and reading it is what lets
// `den doctor` say "too old" instead of "unreadable".
//
// It returns "" rather than an error when it cannot find one: an unreadable
// version is the CALLER's question — source.CheckCompatibility turns it into
// an UnknownVersionError, `den doctor` into a warning — and a version den
// cannot read must never be turned into a number it then compares.
func ParseVersion(output string) string {
	for _, line := range strings.Split(output, "\n") {
		_, rest, ok := strings.Cut(line, "sbx version")
		if !ok {
			continue
		}
		fields := strings.Fields(strings.TrimPrefix(rest, ":"))
		if len(fields) == 0 {
			return ""
		}
		return fields[0]
	}
	return ""
}
```

```python
"""Rewrite {"sandboxes":[...]} / {"images":[...]} to bare arrays in Go source.

For each opener, scan forward counting brackets to the array's matching ']',
then drop the wrapper's closing '}' that follows it. Works across Go string
concatenations because the Go code between JSON segments holds no brackets in
these files; a mismatch aborts with the offset.
"""
import pathlib
import re
import sys

OPEN = re.compile(r'\{\s*"(?:sandboxes|images)"\s*:\s*\[')


def migrate(text, path):
    out, i = [], 0
    while True:
        m = OPEN.search(text, i)
        if not m:
            out.append(text[i:])
            return "".join(out)
        out.append(text[i:m.start()])
        out.append("[")
        j, depth = m.end(), 1
        while depth:
            if j >= len(text):
                sys.exit(f"{path}: unbalanced list at offset {m.start()}")
            c = text[j]
            if c == "[":
                depth += 1
            elif c == "]":
                depth -= 1
            j += 1
        k = j
        while text[k] in " \t\r\n":
            k += 1
        if text[k] != "}":
            sys.exit(f"{path}: no wrapper brace after the list at offset {m.start()}")
        out.append(text[m.end():j])
        i = k + 1


for name in sys.argv[1:]:
    p = pathlib.Path(name)
    src = p.read_text(encoding="utf-8")
    dst = migrate(src, p)
    if dst != src:
        p.write_text(dst, encoding="utf-8")
        print("rewrote", p)
```

```go
// decodeList reads an sbx `--json` listing into v, a pointer to a slice.
//
// sbx v0.48.0 returns listings as a bare array (measured 2026-10-13 on `ls`
// and `template ls`); up to v0.47.0 it wrapped them in an object
// (`{"sandboxes":[…]}`). den supports v0.48.0 and later only, so the object
// is RECOGNIZED to be refused with the remedy, never read: decoding it would
// be compatibility nobody tests, and reading it as an empty list would make
// `den exec`/`den rm` claim a live sandbox does not exist.
//
// The JSON literal null decodes to an empty slice, like `[]`. Any other value
// fails with the raw output, for the reason DecodeJSON gives.
func decodeList(command string, output []byte, v any) error {
	var raw json.RawMessage
	if err := DecodeJSON(command, output, &raw); err != nil {
		return err
	}
	if trimmed := bytes.TrimSpace(raw); len(trimmed) > 0 && trimmed[0] == '{' {
		return fmt.Errorf("sbx %s: output has the pre-v0.48.0 shape — den requires sbx %s or "+
			"later; upgrade sbx, then check with `den doctor`", command, MinVersion)
	}
	if err := json.Unmarshal(raw, v); err != nil {
		return fmt.Errorf("sbx %s: unreadable JSON output (%w): %s", command, err, string(output))
	}
	return nil
}
```
